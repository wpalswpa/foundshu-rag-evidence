# 검색 비교 기록과 해석

`retrieval-record.json`은 2026-10-12 KST에 수행한 원본 로컬 실행의 사례별 결과다. 개인이 만든 합성 입력이며 외부 전문가의 정답 검수나 실제 보험사 결과와의 대조는 없었다.

## 평가 구성

- 자료: 두 회사 문서의 지정 15쪽(KB 6쪽, 다른 회사 9쪽), 검색 조각 79개.
- 사례: 24개. 조항이 필요한 18개는 한 상품의 세 특약에 집중돼 있고, 나머지 6개는 범위 불명·불일치 사례다.
- 정답: 필요 조항 묶음 19개. 두 묶음이 필요한 사례도 있어 사례 수와 다르다.
- 방법: A 범위 없는 낱말 검색, B 범위 제한 낱말 검색, C B에 개념 낱말 추가, D 기존 조항 묶음, E 범위 없는 의미 검색, F 범위 제한 의미 검색.
- 의미 검색: 로컬 Ollama의 KURE-v1 임베딩. 모델 답변 생성은 사용하지 않았다.

## 해석

A와 E는 24개 사례 모두에서 범위 밖 인용이 하나 이상 있었고, B와 F는 없었다. 범위 밖 인용이 없다는 것만으로 모든 인용이 의미상 적합하다고 볼 수는 없다. D는 조항을 더 많이 반환하므로 상위 5개인 다른 방법과 회수율만으로 우열을 비교하지 않는다.

생성형 시험판은 별도 경로다. 조건표·조항 등을 500자 안팎, 80자 겹침으로 나누고 임베딩 검색 상위 10개를 qwen3 4B에 전달했다. 자료 해시로 벡터 캐시를 관리하고, 입력 실측에 맞춰 문맥 크기를 정했다. 그러나 검색한 제외 조항과 답변의 모순이 관찰돼 생성 답변을 기본 판정에 쓰지 않는다. 생성 안전 검사 전체의 완료나 정확도 향상은 이 저장소에서 주장하지 않는다.

## 검사가 확인하는 것

`python evidence/check_record.py`는 144개 행(24개 × 6방법)에서 합계를 다시 계산하고 캡처의 해시를 대조한다. 실제 원문에서 검색을 다시 수행하거나 E/F의 임베딩 모델을 실행하는 명령이 아니다. 기록된 시간은 한 번의 로컬 실행값이며 서비스 응답 시간이나 사용자의 처리시간 절감으로 해석하지 않는다.

원문 약관과 합성 사건 상세는 공개하지 않았다. 따라서 공개 독자는 정답 라벨의 타당성이나 인용 ID의 의미 적합성을 이 기록만으로 독립 검증할 수 없다. 이를 위해서는 공개 가능한 별도 평가 자료와 제3자 정답 검수가 필요하다.
