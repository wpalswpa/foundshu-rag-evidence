# 찾았슈 검색 근거 공개 설계

이 문서는 공개 재현의 범위와 검증 기준이다. 서비스 전체와 보험금 지급 판단은 구현 범위에 포함하지 않는다.

## 목적과 범위

보험 청구를 준비하는 사람이 자기 계약과 다른 특약의 문구를 근거로 받는 문제를 다룬다. 독자는 검색 구현을 검토하는 개발자다. 결과물은 계약 범위 검색의 실행 코드, 가상 자료, 자동 검사, 원본 서비스 화면과 비교 실험 기록이다.

원본 서비스는 비공개로 유지한다. 약관 PDF·인용 원문, 고객·담당자 자료, 계약 데이터베이스, 계정·비밀값, 사업계획과 제출 서류는 옮기지 않는다. 화면은 예시 자료로 촬영된 기존 캡처에서 식별정보와 약관 원문이 없는 것만 고른다.

## 검색 흐름과 결정

질문과 계약의 회사·상품·판본·특약을 받는다. 정확히 하나의 문서와 특약이 연결될 때 해당 범위만 검색한다. 판본이 비었거나 문서가 없거나 둘 이상이면 근거를 붙이지 않고 보류한다. 제목이 비슷하다는 이유로 다른 특약을 대신 쓰지 않는다.

원본의 글자 두 개 단위 BM25 점수식을 작은 함수로 옮긴다. 검색 전 범위 제한을 적용하므로 문서 빈도와 평균 길이도 해당 후보 안에서 계산된다. 원문 위치와 해시를 검증한 뒤 인용을 반환한다. 검색 순위에서 빠질 수 있는 같은 특약의 정의·제외·감액·기간·사건 조항은 근거 묶음에서 함께 보인다. 점수가 없으면 묶음도 반환하지 않는다.

원본 PDF 파서·계약 업무·온톨로지·모델 호출을 통째로 복사하는 대안은 공개 범위와 실행 의존성이 커 제외했다. 공개 코드에서는 직접 작성한 가상 문서를 쓴다. 로컬 모델로 실행한 원본 A~F 실험은 인용문을 제거한 사례별 집계 기록으로 제공한다. 이 기록의 합계를 다시 계산할 수 있지만 원본 검색과 임베딩을 이 저장소만으로 재실행할 수는 없다.

검색 적합성, 생성 답변 정확성, 실제 지급 결과는 서로 다른 평가다. 생성형 시험판은 원문과 모순된 답을 낸 사례가 있어 기본 판정 경로에서 제외했다. 공개 코드는 답변을 생성하거나 지급 여부를 결정하지 않는다.

## 검증과 완료 기준

| 요구 | 산출물 | 통과 기준 |
|---|---|---|
| 계약 범위 검색 | `retrieval.py`, `examples/corpus.json` | 다른 회사·상품·판본·특약이 결과에 섞이지 않음 |
| 불확실할 때 보류 | 자동 검사 | 판본 누락·중복 문서·미등록 특약·빈 질의에서 인용 없음 |
| 원문 근거 | 자동 검사 | 위치·해시·인용문 변조를 거부함 |
| 근거 묶음 | 자동 검사 | 낮은 순위의 같은 특약 제외 조항을 함께 반환함 |
| 비교 기록 | `evidence/retrieval-record.json`, 검사 | 사례별 기록에서 공개 요약을 다시 계산해 일치함 |
| 실제 화면 | `docs/images/`, 화면 출처 | 가상 자료임을 확인하고 식별정보·원문이 없는 캡처만 포함 |
| 공개 파일 | Git 변경 목록, 별도 검토 | 허용 파일만 포함하고 CI 성공 뒤 병합 |

구현과 검증 담당은 저장소 작성자이며 별도 검토자가 공개 범위와 주장을 원천에 대조한다. 모든 검증은 최초 공개 전에 수행한다. 공개 이후에도 원본의 검색 정확도나 실사용 성과로 범위를 넓혀 주장하지 않는다.
